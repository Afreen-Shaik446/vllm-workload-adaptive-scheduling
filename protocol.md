# Amended candidate protocol — 2026-11-05 (Pacific)

Status: software-only validation; GPU pilot and calibration pending. This is an amendment before GPU observations, not a claim of prior preregistration. Archive both this amendment and the original protocol. No publication or novelty claim.

Hypothesis: a queue/decode-pressure budget heuristic may improve first-text tail latency during mixed prefill/decode pressure; it may also worsen prefill waiting or do nothing under decode-only traffic. Prespecify throughput/fairness guardrails, then report beneficial, harmful and unchanged cases alike.

## Sequence and controls

1. Authenticate to free Colab first. Confirm a free GPU runtime is actually assigned. Capture GPU name/UUID, memory, driver, CUDA, vLLM/torch/transformers versions and full pip freeze. A Colab page is not a GPU allocation. If incompatible/unavailable, stop and preserve logs. Never buy compute or provision RunPod without explicit approval, including existing-credit consumption.
2. On the GPU, resolve **vllm==0.32.0** in an isolated environment; inspect exact installed source/signature and run `pip check`. Version metadata captured here requires Transformers >=5.16.1,<5.20.0; the original `<5` cap conflicts. CUDA/driver compatibility is hardware-specific and has not been tested. Versioned installation docs and release page give different default CUDA descriptions: inspect resolved torch/CUDA rather than assuming either.
3. Start `stock_2048` and save an actual generated response with `scripts/smoke.py`. Only then attempt the subclass. Use pinned Qwen2.5-1.5B-Instruct revision 989aa7980e4cf806f80c7fef2b1adb7bc71aa306, float16, 4096 context. It is a modest pilot candidate, not a demonstrated fit on an unseen GPU. Do not silently change model/precision or vLLM version to obtain a pass.
4. Run a separate pressure/integration pilot with every-step logging. Require nonempty real engine allocations at multiple budgets, including a reduced budget, and verify allocation totals never exceed the chosen budget. Check class names, PID, version and generated responses. A server launch, fake-parent test or unchanged budget is insufficient evidence of adaptation. If all fixed/adaptive workload budgets are unchanged, report no exercised adaptation for those conditions.
5. Main fixed sweep: 256, 512, 1024, 2048 scheduled tokens with common 2048 execution capacity and max-num-seqs=64, chunked prefill on, async/prefix caching off. All static conditions use a no-adaptation audit subclass so logging overhead is matched. Separately compare stock with instrumented fixed_2048 to assess instrumentation overhead; performance conclusions are scoped to synchronous scheduling. External request admission is open-loop with no active-request cap or adaptive ordering. Internal engine concurrency remains 64.
6. **Calibration before confirmation:** sweep fixed budgets on disjoint seeds and several offered rates, including below, near and above each workload's sustainable capacity; record actual offered rate and failures. Select rates and best fixed comparator by a written rule using calibration results, then freeze the main JSON protocol and trace hashes. Report all four static policies, even those that lose. The included 8 requests/s is an arbitrary pilot rate and must not be called tuned. A 128-request pilot is not tail evidence.
7. Confirmatory candidate: six families (stable/bursty short, stable/bursty mixed, stable/bursty decode-heavy), at least five paired seed blocks, 2400 requests per run. Mixed workloads target half long requests; check realized long count >=1000 before interpreting long P99. Use exactly shared traces and decoding seeds within each paired condition. These are independent workload seeds, not repeats of identical traces; add repeats with distinct repetition IDs if assessing same-trace noise. Current runner does not support duplicate condition IDs, so keep such repeats in separate complete experiment roots.
8. Restart server for every run; identical short/long warmups, model response smoke, prefix caching off, drain after all arrivals. This is warmed-kernel/empty-live-KV evaluation; it is not a cold model-start comparison. Identical warmups do not guarantee identical CUDA graph state across dynamic shapes: inspect startup/graph logs. Randomize policy order with recorded seed 6172. Log GPU identity/load/thermals before and after; no hardware migration within comparisons.
9. Log every policy's requests (including failures), raw streaming events, actual scheduler decisions, server stdout, metrics before/after and environment/config hashes. Main audit sampling=100 steps reduces overhead but misses some transitions. Repeat a subset with logging off and every-step audit to quantify overhead; keep these in separate roots and never pool configurations. Current runner captures environment at matrix start; per-run utilization/temperature monitoring still needs operator instrumentation.
10. Run audited analysis and the separate stdlib recomputation. Validate hardware/server provenance manually; a marker JSON is not proof. Carry all scheduled requests into completion denominators. Flag generator lag >50 ms, incomplete protocols, missing usage, token mismatches, crashes and censored requests. Never silently omit a failed matrix.

## Proposed guardrails (lock before confirmation)

Compare against the fixed policy selected on disjoint calibration seeds: at least 95% valid output-token throughput; long P95 client TTFT <=110%; completion decrease <=1 percentage point; no unreported invalid requests. These thresholds are design choices, not existing findings. Require adequate per-group tail counts and report paired run-block uncertainty. Five blocks remain limited; do not claim significance from overlapping or sparse exploratory intervals. No automatic pass/fail performance finding is emitted.

## Remaining limitations

See METRICS.md: client chunk gaps are not true ITL; server queue waiting is not yet instrumented per request. The policy's decode count is a proxy and does not use KV occupancy or output-length oracle. Hysteresis includes an initial hold before entering congestion; retained deliberately pending calibration. The queue signal omits specialized upstream deferred/KV queues. No starvation guarantee, multi-GPU, speculative decoding, async, multimodal or prefix-cache study. Synthetic forced lengths with ignore_eos are controllable but not natural user behavior. Small-model conclusions do not generalize to large models. Published adaptive baselines have not been reproduced. Original literature references P-PAS/SLOWeave could not be independently retrieved in this pass and should be verified before application use; no novelty inference is based on them.
